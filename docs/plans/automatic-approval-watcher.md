# 办公助手自动审批值守实施计划

> 2026-07-29 更新：本文原有“10 分钟、三天影子期、第三次转人工、处理结案”的设计已被 ADR-0011 和当前实现取代。有效口径为只处理 `status=1` 立案、每 3 分钟扫描、首次发现后 2 分钟复读、直接自动写入、业务异常驳回、技术异常重试、Windows 为主要审批主机、飞书可选。

## Outcome

Windows 版办公助手可在系统托盘长期值守。审批账号显式开启自动审批后，系统每十分钟检查全所待审案件，按可验证规则自动通过、自动驳回或转人工，并通过 `approval.gaodazhuang.top` 协调全所唯一自动写入端和审计记录。首次上线只运行三天影子模式，必须由审批人审阅报告并手动确认后才能正式写入 OA。Codex Sites 提供公开安装包下载和版本说明，应用发现新版本后提示用户确认更新。

## Decision model

每件 `status=1` 案件只产生一个结果：

1. **自动通过**：所有适用规则均明确通过，没有未知、警告或人工判断项。民事、刑事、非诉和风险代理均不按类别排除。
2. **自动驳回**：存在能够可靠证明的明确阻断项。相同驳回指纹最多自动驳回两次，第三次转人工。
3. **转人工**：存在姓名利冲线索、条款不可判定、资料无法可靠解释、第三次相同提交或其他人工判断项。

明确利冲必须同时确认可靠主体标识、案件对立方向和相关案件仍在办理；仅姓名相同不得自动驳回。风险代理只审查 OA 记载条款的适用范围、权利限制、收费基数、计算方式和累计上限，不验证合同或告知材料。

## Architecture

### Desktop client

- Windows 登录系统后启动托盘值守；关闭主窗口不退出后台。
- 登录页使用 OA 账号和密码换取访问令牌，不向普通用户展示 API Key 登录。
- “保持登录”由用户显式选择；勾选后密码按账号存入 Windows 凭据管理器或 Mac 钥匙串，账号、密码、API Key 和长期令牌均不得写入 `localStorage`。
- 自动审批只有在当前审批账号开启“保持登录”时才能启用；令牌失效后使用系统凭据库自动重登，重登失败立即停止自动写入。
- 登录后读取 OA 返回的实际审批权限，不按姓名、职位或本地名单推定。
- 无审批权限时完全隐藏“案件审批”入口、不轮询待审数量；通过旧链接进入时显示无权限页面。
- 审批查询、检查和写入接口均在后端再次校验审批权限，前端隐藏不能代替服务端授权。
- 原“案件看板”入口和页面统一更名为“案件列表”，避免与独立案件看板产品混淆。
- 用户点击下载所选文书后先打开原生目录选择框；用户取消选择时不导出、不写入任何文件，不再固定保存到桌面。
- 自动审批开关默认关闭，切换 OA 账号后不得继承开关状态。
- 每十分钟轮询待审队列；打开审批页和“立即检查”触发即时查询。
- 写入前重新读取案件状态和规则输入，状态不再是 `1` 时跳过。
- 登录、网络或租约异常时停止自动写入。

### Coordination service

- Cloudflare Worker + D1，绑定 `https://approval.gaodazhuang.top`。
- 设备通过一次性配对码取得独立凭据；协调服务不接收 OA 账号、密码、API Key 或访问令牌。
- 全所自动审批权由一个“审批账号＋设备”租约持有，每分钟续期，十分钟离线自动释放，支持显式强制接管。
- 只保存律所、案件标识、审批账号、设备、租约、动作、规则版本、时间和结果等元数据；不保存当事人姓名、案件正文或证据材料。

### Audit

- OA 审批意见标记自动通过或自动驳回、规则版本和简短审计编号。
- 自动驳回写明原因和第几次驳回。
- 写后回读校验预期状态，校验失败记录异常并暂停该案件的自动处理。
- 值守设备在自动动作完成后发送系统通知。

### Distribution and updates

- Codex Sites 提供公开下载页面、版本说明、安装包和机器可读更新清单。
- 公开站点直接使用 Sites 提供的生产地址；本阶段不购买或绑定新的付费品牌域名。
- 应用启动时及每二十四小时检查一次版本；发现新版后提示用户确认，不执行静默强制更新。
- 下载后校验 SHA-256 和发布签名，再启动安装程序；校验失败时停止安装并提示用户。

## Delivery phases

1. **仓库保护与同步**：备份当前未提交改动；基于 `origin/main` 最新 Windows 修复建立 `codex/automatic-approval-watcher` 分支；逐项恢复非诉放宽和本轮文档，禁止覆盖用户改动。
2. **规则核心与测试**：把审批规则从 HTTP/UI 解耦为可测试核心；为自动通过、自动驳回、转人工、驳回指纹、明确利冲、风险条款和非诉规则建立单元测试。
3. **协调服务**：实现设备配对、租约获取/续期/释放/强制接管、审计和影子报告接口；部署 D1 与 Worker，绑定域名并验证 HTTPS。
4. **桌面集成**：实现账号密码登录、系统凭据库存储和令牌续期，再实现协调客户端、账号级开关、租约状态和托盘控制。
5. **自动审批执行器**：实现十分钟轮询、逐案串行判断、写前复核、OA 意见标记、写后回读、两次驳回上限和系统通知。
6. **Windows 交付**：更新安装器与开机自启配置，生成可安装包；在 Windows 真机验证 WebView2、托盘、凭据、双端登录和异常恢复。
7. **下载站与应用更新**：创建 Codex Site，使用 Sites 生产地址发布安装包、版本说明和更新清单；实现应用内版本检查、下载校验和用户确认安装。
8. **三天影子运行**：只记录模拟决策，不写 OA；生成与人工结果对比报告。三天后由审批人手动确认，样本少于五件时二次确认，存在相反结果时默认继续影子运行。

## Acceptance criteria

- 默认登录、开机或切换账号不会开启自动审批。
- 普通用户可使用 OA 账号密码登录；浏览器存储中不存在账号密码或 API Key。未开启“保持登录”的账号不能开启自动审批。
- 有审批权限的账号显示“案件审批”并查询待审数量；无审批权限的账号完全隐藏该入口且不发起待审轮询，直接访问审批地址时前后端均拒绝。
- 同一律所同时只有一个账号设备组合能够自动写入，强制接管后旧端立即失去写入权。
- 租约连续十分钟未续期后可被其他设备取得。
- 自动通过只发生在所有适用规则明确通过时；任何未知或人工项均转人工。
- 相同驳回指纹只自动驳回两次，第三次不再自动写入。
- OA 意见和协调服务记录能够用同一审计编号对应，且 D1 不含当事人姓名或案件正文。
- 三天影子运行结束前以及审批人手动确认前，不发生自动 OA 写入。
- 公共下载站可获取当前 Windows 安装包和版本说明；应用能够发现新版本、校验更新包并在用户确认后启动安装。
- 左侧入口和页面标题统一使用“案件列表”；每次文书下载均由用户选择保存目录，取消选择不会产生文件。
- TypeScript、Python、Worker 单元测试和协调服务并发租约测试通过；前端构建、Windows 打包和 Cloudflare 部署检查通过。

## Explicit exclusions

- 不实现结案审批。
- 不检查风险代理合同、告知书等材料的存在或真实性。
- 不允许多个自动写入端处理同一全所队列。
- 本阶段不补齐 Windows 的 OCR、微信录屏取证或证据整理工具链。
- 不执行未经用户确认的静默或强制更新。
- 未经另行授权，不推送 GitHub、不创建 PR、不在 Windows 真机安装。

## Known implementation checks

- 当前本地 `main` 比 `origin/main` 落后三个 Windows 修复提交且存在未提交改动，必须先安全合并。
- 必须实测同一 OA 账号在 Mac 与 Windows 同时登录时 Token 是否互相失效。
- 必须核实 OA 是否能稳定提供身份证号或统一社会信用代码；无法取得可靠主体标识时，利冲只转人工。
- 正式公开发布前必须确认 Windows 安装包签名方式及 Sites 对安装包体积的承载方案；不以购买自定义域名作为发布前提。
